# Data-Analysis

本仓库放着定量调研的数据集清洗脚本，一份脚本对应一轮投放的数据。脚本从平台导出的原始 CSV 出发，
产出可以直接喂给 R 或 Python 的分析文件，同时把它自己的动作写进一份可读的日志。

目前只有一个：`092601_cleaning.py`，把 600 份日本 MMORPG 玩家问卷的原始导出收成分析文件。

## 用法

把原始导出放在 `data/Original.csv`，然后

```
python 092601_cleaning.py
```

产出四个文件，都落在 `data/` 下面：`RPG.csv` 是主数据，600 行 × 426 列；`值码表.csv` 记着 116 条
编码规则；`各题分母.csv` 逐题写明清洗后的有效 N 与三种缺失码各占多少格；`清洗日志.txt` 是脚本
做了什么、动了多少格的完整交代。换路径就把输入输出作为两个参数传进去；加 `--check` 只重算并与
磁盘上现有的产物逐格比对，不写盘——脚本改了或者数据换了，比对会告诉你哪一行先不同。

只依赖 Python 标准库，没有第三方包。脚本可重跑，跑几次结果都一样；自检不通过时它会抛出全部
未通过项并不写盘，宁可停下也不产出半对的表。

原始导出是 600 行 × 438 列，前两行都是表头：第一行是变量名，第二行是题目与选项正文。读的时候
记得跳过第二行，它不是数据。文件里只有完成的访谈，甄别被终止的人不在其中，所以 600 人本身
就等于合格样本，样本口径不需要裁切。

## 清洗做了什么

顺序与问卷流向一致。每一步先算「谁该答这道题」，再决定这格保留、作废还是写缺失码；方向只有
一个，用前面的答案决定后面那道题作不作数，不拿后题反推前题。

S2 只对 S1 勾了 RPG 的 551 人出示，另 49 人在本题写 97。Q2 全卷作答，其中 69 人走了逃亡口，
跳过 Q3，这 69 人的 Q3 全部写 97。Q3 的逃亡口在实投时没有生效：217 名说「一款都没玩过」的人
被继续问了 Q4，还多带进了 Q22，而 Q4 的选项集本来就是由各人 Q3 的勾选生成的，对他们不成立。
清洗把这 217 人在 Q4 与 Q22 上的作答作废，写 97，Q4 的有效人群回到设计的 314 人。作废作答
而不是剔除样本，是因为这 217 人在 Q3 以及 Q9 之后的每一道题上都有有效作答，删人会连带毁掉
支线与后段各题的分母。Q4 还收着一个从 Q3 串过来的文本项，整项作废。

Q5 到 Q8 只问自报的那一款，215 人作答；Q9 到 Q12 是平行支线，385 人作答。有 2 人两段都答了，
按流向只该走主支，他们在 Q9 至 Q12 的作答作废，样本保留。两支恰好覆盖 600 人。

Q17 与 Q28 两题在投放时没有出出来，数据集里连选项列都没有，四列全空，写 99。这里的 99 是
「整题无数据」，与跳转不适用不是一回事，读报告的人要能看到这个区别，所以列保留作占位，等重新
导出后回填。Q18 至 Q20、Q23、Q26、Q27 在实投时对全卷 600 人作答，设计上只该问 MMORPG 玩家，
门槛没落位；清洗不动这些数据，只在表末加 `is_mmorpg` 等三个标记，分析时统一用它筛出 288 人，
全卷口径只作附录对照。Q24 与 Q25 的门槛落在 Q23 的「独狼」上而不是 MMORPG 上，同样交给筛。

Q22 是评分矩阵，17 个行标记配 17 个评分块，每块八条说法。清洗做三层：Q3 逃亡口的 217 人作答
作废；平台自己加的第 18 行「一款都没玩过」整块作废；其余空格写缺失码，这些空格来自各人没勾过
的游戏行。清洗后行标记与 Q3 的勾选逐行一致，这一点脚本每次都会重算复核。

## 表末三列与一个键

`is_mmorpg` 标记 MMORPG 玩家，S1 或 S2 任一处勾了就是 1，两处并集 288 人。作并集是因为 S2 的
MMORPG 一项对 S1 已勾的人隐藏，而一部分日本玩家并不把 MMORPG 当作 RPG 的子类，只看一处会漏人。
`branch` 标记问卷的两条腿，主支 215 人、支线 385 人。`elig_q4` 标记该不该答 Q4 与 Q22。

第一列 `ID` 是 1 到 600 的行序，用来 join 与按人聚类；平台序列号 `iirepSerial` 留在第 422 列，
用来向平台回溯。这两列里的 97、98、99 是真实取值，不是缺失码，脚本只对问卷变量区做缺失码替换，
每次都会独立核对这两列没被动过。

## 缺失码为什么拆成三个

UK Data Service 的规范把「不适用」按原因分开记，一份归档件同时得是开箱即用的分析文件，所以
这里也拆：97 是跳转未出示，以及清洗时事后作废的作答；98 是明确表示不愿回答或不便回答，共 44 格，
这几题的分母要扣掉 98 再写 N；99 是无可用记录，包括整题无数据、开放题没有文本、性别落不进二值
的那一格。95 与 96 本卷不用。作废的作答并进 97 而不是单立一码，理由是清洗之后这些格在功能上
就不在本题的应答题人群里，算分母时一刀切反而清楚。

多选拆成 0/1 的哑变量，不并成逗号串。这是 SPSS 多重应答集的 multiple dichotomy 写法，GESIS 的
操作规范原文就要求这么编；并成串会把「一个选项都没勾」和「本题没出示」压成同一种状态，而 Q22
那种 17 款游戏乘 8 条说法的矩阵也没法用串表达。矩阵题的矩阵性放在元数据层，数据形状不动，
要跑混合模型之类的分析时再转长表。

## 已知问题与一处待裁决

Q17 与 Q28 无数据，退回需求方确认是导出不全还是这两题没投，分析先行跳过并注明。

Q3 的逃亡口没生效、Q4 多一个逃亡项、Q22 多一行，是同一个平台逻辑问题，数据已按上面的口径处理。
主支与支线那 2 人重叠是 0.3% 量级的噪声，已按主支归位。

Q9 至 Q12 那 2 名异常人在 Q9 开放填空上的作答按口径应记 97，现有数据里这两格是 99——当年先用
99 做单一占位码，拆码时把开放列整列保留成 99，漏掉了这两格。脚本默认照现有数据写 99，好让
第三方能逐格复现；要改成 97，把文件头的 `VOID_OPEN_TEXT_AS_97` 置 True 再重跑即可，只动这 2 格。

Q24 与 Q34 的开放伴随列在原表里一字未填，两列整列被记成 97。按本仓库的口径，出示了但没写应该
记 99、跳转未出示才记 97，这两列现在分不开这两种情况。
